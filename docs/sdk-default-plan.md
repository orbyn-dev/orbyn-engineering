# Claude and Cursor SDKs in the engine host: plan

The Claude Agent SDK and the Cursor SDK may be used (decision of 2026-11-22), on the condition that Orbyn Engineering is open
source for public use. Nothing below is built yet unless it says so. Each step is its own small pull request.

Rules that stay: Orbyn never collects, reads or stores Claude.ai credentials; the `claude` binary is the person's own and is not
modified; the SDKs are dependencies used as shipped, never copied; any licence or notice file an SDK asks for ships with the app.
The written permissions are not copied into the repository.

| Step | What | Status |
| --- | --- | --- |
| 1 | This document and the wording of architecture rule 3, handoff.md and the engine-host README | this change |

| 4 | Packaging: a production `node_modules` with the two SDKs in the app resources beside the host binary, loaded by the host from that path (the single-file bundle cannot hold native files); the Claude SDK runs against the person's own `claude` through `pathToClaudeCodeExecutable`, so the SDK's own platform binaries are left out; native files signed; `scripts/check-macos-entitlements.sh` walks them | Built, not yet run in a real bundle: `engine-host/scripts/prepare-sdks.mjs` writes `engine-host/dist/sdk` (111 packages from the lockfile, `npm ci --omit=dev --ignore-scripts`, no Claude platform packages, the Cursor package for the build platform, `THIRD_PARTY_NOTICES.md` beside it); `prepare-bundle` stages it as the app resource `sdk` (`Contents/Resources/sdk`, macOS arm64 only; other targets get an empty folder); the host loads from `sdk/` beside its executable, then `../Resources/sdk`, else the package name; `sign-adhoc-macos.sh` signs the Mach-O files in it and the entitlement check walks them |
